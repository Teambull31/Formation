# Gmail et écrire son propre connecteur

Vos mails ne viennent pas toujours d'une API toute faite. Parfois c'est Gmail, parfois un dossier de fichiers exportés. Bonne nouvelle : grâce à l'interface `MailSource` (leçon 5), brancher une nouvelle boîte, c'est écrire **une seule méthode**, `fetch`. Le reste du digest ne change pas.

## Gmail : lecture seule, par OAuth

Gmail se lit avec son API. Vous demandez un seul droit : **`gmail.readonly`**. Pas d'envoi, pas de suppression, pas de « marquer comme lu ». La première fois, une page Google vous demande d'accepter ; le script reçoit un **jeton**, rangé dans un fichier en 0600.

!!Un jeton Gmail donne accès à toute la boîte : jamais dans git, jamais dans un log!!

Le kit contient `GmailSource`. Vous le testez contre le simulateur `mock_gmail`, jamais contre votre vraie boîte. Un compte Google **professionnel** exige l'accord du service informatique, comme pour Outlook.

## L'alternative : IMAP

IMAP est un protocole plus ancien, accepté par presque toutes les messageries. Le kit fournit `ImapSource`. Deux règles : ouvrir le dossier en **`readonly=True`** et lire le mot de passe dans une **variable d'environnement**, pas dans le code. !!Un mot de passe dans le script finit tôt ou tard sur un dépôt!!

## Le contrat MailSource

Un connecteur est une classe avec `fetch(since=None, limit=50)`. Elle renvoie des `Mail` : `id`, `sender`, `subject`, `received` (ISO 8601 en UTC), `body`. Elle est **bornée** (`limit` respecté, `limit <= 0` donne une liste vide), tolérante (un champ manquant reçoit une valeur de repli, sans exception) et **en lecture seule**.

!!Ne journalisez jamais un corps de mail ni un jeton : des compteurs, pas du contenu!!

## Un connecteur maison : un dossier de `.eml`

Un fichier `.eml` est un mail complet enregistré tel quel. Le kit sait déjà le lire : `message_to_mail` transforme un message en `Mail`. Votre connecteur ne fait que quatre choses : lister les `*.eml` du dossier, les lire, convertir chacun, puis laisser `_select` trier et appliquer `since` et `limit`. Pièges : un fichier `notes.txt` ou un sous-dossier n'est pas un mail, et un `.eml` sans `Message-ID` a besoin d'un identifiant de repli (le nom du fichier).

!!Testez contre des données jetables et comparez avec une source connue : sur les mêmes mails, deux sources doivent rendre exactement les mêmes résultats!!

## Exemple

```python
class EmlDirSource:
    def __init__(self, path):
        self.path = Path(path)

    def fetch(self, since=None, limit=50):
        if limit <= 0 or not self.path.is_dir():
            return []
        mails = [message_to_mail(email.message_from_bytes(f.read_bytes()), f.stem)
                 for f in sorted(self.path.glob("*.eml")) if f.is_file()]
        return _select(mails, since, limit)
```

**À retenir :** un connecteur = `fetch` + le contrat (lecture seule, borné, tolérant) ; Gmail en `gmail.readonly`, IMAP en `readonly=True` ; on teste contre un simulateur et on compare avec une source connue ; jamais de contenu de mail ni de jeton dans les logs.
