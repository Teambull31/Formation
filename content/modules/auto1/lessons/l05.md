# Une source de mails derrière une interface

Votre automatisation lit des mails. Aujourd'hui dans un fichier de test, demain dans une boîte réelle. Si le reste du code ne change pas entre les deux, vous avez gagné des heures.

## Le contrat MailSource

Le kit définit un **contrat** : un objet `MailSource` n'a qu'une méthode, `fetch(since=None, limit=50)`. Elle renvoie une liste de `Mail`, les plus récents d'abord. Peu importe d'où ils viennent.

Un `Mail` est une `dataclass` figée avec cinq champs : `id`, `sender`, `subject`, `received` (date ISO en UTC) et `body`. Les champs ne changent pas d'une source à l'autre.

## Pourquoi isoler la source

Le tri, le résumé et l'affichage ne doivent pas savoir si les mails viennent d'un **JSON**, d'un fichier **mbox** ou, plus tard, d'IMAP. Seule la ligne qui construit la source change : `JsonMailSource(chemin)` ou `MboxMailSource(chemin)`. Le reste du script appelle `fetch` et rien d'autre.

!!Écrire un `if source == "json"` autour de l'affichage : vous dupliquez le code, et les deux versions divergent!!

## Lecture seule et limite

`fetch` **ne modifie jamais** la source : pas de suppression, pas de marquage « lu ». Un test sur vos vrais mails ne peut donc rien casser. Le paramètre `limit` borne le nombre de mails : demandez `limit=5` plutôt que tout charger en mémoire.

!!Les sources du kit renvoient une liste vide pour un chemin inexistant : à vous de vérifier le fichier et d'afficher une erreur claire!!

## Règle de confidentialité

Les mails réels restent **en local**. Vous ne les envoyez jamais à Claude, ni à aucun service externe, ni dans un journal. Pour vous entraîner, utilisez les fixtures du kit, qui sont fictives.

!!Coller un vrai mail dans un chat pour « voir si ça marche » est une fuite de données!!

## Exemple

```python
from mail_source import JsonMailSource, MboxMailSource

source = JsonMailSource("mails.json")  # ou MboxMailSource("boite.mbox")
for mail in source.fetch(limit=5):
    print(f"{mail.sender} | {mail.subject}")
```

## Importer le kit depuis un script voisin

Le kit n'est pas un paquet installé : c'est un dossier `kit/` posé à côté de votre script. Python ne le trouve pas tout seul. On ajoute donc son chemin **avant** l'import, et on le calcule à partir du script lui-même, pas du dossier courant :

```python
import sys
from pathlib import Path

KIT = Path(__file__).resolve().parent / "kit"   # le dossier kit À CÔTÉ de ce fichier
sys.path.insert(0, str(KIT))                     # ← AVANT l'import, sinon ModuleNotFoundError

from mail_source import JsonMailSource, MboxMailSource   # noqa: E402 (import après le chemin)
```

Pourquoi `__file__` plutôt que `"kit"` tout court ? Un chemin relatif dépend du dossier où l'on **lance** la commande. Lancé depuis cron ou depuis un autre dossier, `"kit"` ne pointerait nulle part.

## Le programme complet

```python
# Fichier : lister.py   Usage : python3 lister.py --source json|mbox --path FICHIER
import argparse
import sys
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parent / "kit"))
from mail_source import JsonMailSource, MboxMailSource  # noqa: E402

SOURCES = {"json": JsonMailSource, "mbox": MboxMailSource}   # le SEUL endroit qui dépend du format


def main():
    p = argparse.ArgumentParser(description="Affiche les 5 mails les plus récents.")
    p.add_argument("--source", choices=sorted(SOURCES), required=True)
    p.add_argument("--path", required=True)
    args = p.parse_args()

    chemin = Path(args.path)
    if not chemin.is_file():                     # le kit renverrait [] : on vérifie avant
        print(f"Fichier introuvable : {chemin}", file=sys.stderr)
        sys.exit(1)

    source = SOURCES[args.source](str(chemin))   # ← la création : seule ligne qui varie
    mails = source.fetch(limit=5)                # ← à partir d'ici, le code ignore le format
    if not mails:
        print("(aucun mail)")
        return
    for m in mails:
        print(f"{m.sender} | {m.subject}")


if __name__ == "__main__":
    main()
```

Le dictionnaire `SOURCES` remplace un `if source == "json" ... elif ...` : ajouter IMAP demain, c'est ajouter une ligne au dictionnaire, sans toucher à l'affichage. `argparse` vérifie les arguments et affiche l'aide (`--help`) gratuitement ; `choices` refuse une source inconnue avec un message clair.

## Pas à pas : écrire lister.py

1. Regardez le contrat : `grep -n "def fetch\|class " kit/mail_source.py`.
2. Écrivez les trois lignes d'import du kit et vérifiez-les seules : `python3 lister.py` ne doit pas afficher `ModuleNotFoundError`.
3. Ajoutez `argparse` avec `--source` et `--path`, et testez `python3 lister.py --help`.
4. Ajoutez la vérification du fichier, puis la création de la source et la boucle d'affichage.
5. Comparez les deux formats : les deux commandes ci-dessous doivent afficher les mêmes lignes.

```bash
python3 lister.py --source json --path kit/fixtures/mails.json
python3 lister.py --source mbox --path kit/fixtures/inbox.mbox
```

6. Testez l'erreur : `python3 lister.py --source json --path absent.json; echo $?` affiche une phrase sur stderr et `1`.

**À retenir :** un contrat `fetch` unique, un seul endroit où l'on choisit la source, une lecture seule bornée par `limit`, et des mails réels qui ne quittent jamais la machine.
