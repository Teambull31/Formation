# Résumer des mails

Résumer, c'est le travail rêvé pour un modèle local. Mais un modèle bavarde, se trompe et parfois invente. Votre script doit donc lui poser une question précise, vérifier la réponse, et savoir se passer de lui. Rappel : les mails réels restent **en local** (Ollama), jamais envoyés à un service externe.

## Un prompt structuré

Un bon prompt a trois parties, toujours dans le même ordre : les **consignes**, un **délimiteur**, puis le **mail**. Les consignes disent le rôle, le format de sortie attendu et la règle « n'invente rien ». Le délimiteur, par exemple `--- MAIL ---`, marque où commence la donnée. Un mail par prompt : vous gardez ainsi le lien entre un mail et son résumé.

!!Un prompt vague comme « résume ça » donne une réponse différente à chaque appel et impossible à traiter par programme!!

## Demander du JSON, puis le valider

Demandez une réponse au format **JSON** avec des clés fixes : `urgence` et `resume`. Puis ne faites jamais confiance : lisez avec `json.loads`, vérifiez que c'est bien un objet, que l'urgence est dans la liste (`haute`, `normale`, `basse`) et que le résumé n'est pas vide. Une réponse qui ne passe pas la validation est traitée comme une panne.

!!Un `json.loads` sans `try` plante dès que le modèle ajoute « Voici le résumé : » devant le JSON!!

## Découper les gros corps

Un modèle a une fenêtre de contexte limitée, et chaque caractère coûte du temps. **Coupez le corps** à quelques milliers de caractères : le début d'un mail contient presque toujours l'essentiel. Coupez la fin, jamais le début.

## Le résumé extractif de secours

Quand le modèle est éteint, lent ou incohérent, le script produit un résumé **extractif** : un extrait du vrai mail, par exemple ses 200 premiers caractères, avec l'urgence déduite de mots-clés comme « urgent » ou « alerte ». Ce n'est pas brillant, mais c'est vrai, et la chaîne continue de tourner.

!!Un secours qui renvoie toujours « Résumé indisponible » ou une phrase inventée fait croire que le mail a été lu!!

## Ne rien inventer, garder l'ordre

Une entrée par mail, dans l'ordre de la source, même pour un mail vide. Le résumé ne doit contenir que ce qui est dans le mail : chiffres, dates et noms viennent du texte, pas de la mémoire du modèle.

## Exemple

```python
try:
    data = json.loads(generate(prompt, timeout=3))
    ok = data["urgence"] in ("haute", "normale", "basse") and data["resume"].strip()
except (LlmUnavailable, ValueError, KeyError, TypeError):
    ok = False
resultat = data if ok else fallback_summary(mail)
```

## Le prompt tel que le modèle le reçoit

Voici le texte exact envoyé pour un mail, une fois `build_prompt` appliqué. Les trois parties se voient à l'œil nu :

```text
Tu résumes un mail en français. Réponds UNIQUEMENT par un JSON           ← 1. consignes :
{"urgence": "haute|normale|basse", "resume": "une phrase"}.                  rôle, format,
N'invente rien : ne mets que ce qui est dans le mail.                         règle
--- MAIL ---                                                              ← 2. délimiteur, seul sur sa ligne
Objet : Facture n° 2026-0412 à régler avant le 15                         ← 3. la donnée
                                                                              (objet puis corps
Bonjour, vous trouverez ci-joint la facture…                                  coupé à 2 000)
```

Les consignes viennent **avant** la donnée : le modèle lit dans l'ordre, et sait ce qu'on attend de lui avant de lire le mail.

## Le programme complet, fonction par fonction

```python
# Fichier : digest.py   Usage : python3 digest.py --source json|mbox --path FICHIER [--out digest.json]
import argparse
import json
import os
import sys

sys.path.insert(0, os.path.join(os.path.dirname(os.path.abspath(__file__)), "kit"))
from llm import generate, LlmUnavailable
from mail_source import JsonMailSource, MboxMailSource

MARKER = "--- MAIL ---"
MAX_PROMPT_BODY = 2000                  # caractères du corps envoyés au modèle
MAX_RESUME = 200                        # longueur du résumé de secours
URGENCES = ("haute", "normale", "basse")


def load_mails(source, path):
    src = JsonMailSource(path) if source == "json" else MboxMailSource(path)
    return src.fetch(limit=10_000)      # la limite par défaut du kit est 50


def build_prompt(mail):
    return (
        "Tu résumes un mail en français. Réponds UNIQUEMENT par un JSON "
        '{"urgence": "haute|normale|basse", "resume": "une phrase"}. '
        "N'invente rien : ne mets que ce qui est dans le mail.\n"
        f"{MARKER}\nObjet : {mail.subject}\n\n{mail.body[:MAX_PROMPT_BODY]}"   # [:2000] garde le DÉBUT
    )


def fallback_summary(mail):
    texte = f"{mail.subject} {mail.body}".lower()          # casse ignorée
    if any(m in texte for m in ("urgent", "alerte", "critique")):
        urgence = "haute"
    elif any(m in texte for m in ("newsletter", "désabonner")):
        urgence = "basse"
    else:
        urgence = "normale"
    resume = " ".join(mail.body.split())[:MAX_RESUME] or mail.subject   # extrait réel, ou l'objet
    return {"urgence": urgence, "resume": resume}


def summarize(mail):
    try:
        data = json.loads(generate(build_prompt(mail), timeout=3))
        resume = data["resume"].strip()
        if data["urgence"] in URGENCES and resume:
            return {"urgence": data["urgence"], "resume": resume}
    except (LlmUnavailable, ValueError, KeyError, TypeError, AttributeError):
        pass                            # toute réponse inexploitable : même chemin que la panne
    return fallback_summary(mail)


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--source", choices=["json", "mbox"], default="json")
    ap.add_argument("--path", required=True)
    ap.add_argument("--out", default="digest.json")
    args = ap.parse_args()
    digest = [{"id": m.id, **summarize(m), "suspect": False}
              for m in load_mails(args.source, args.path)]   # une entrée par mail, dans l'ordre
    with open(args.out, "w", encoding="utf-8") as f:
        json.dump(digest, f, ensure_ascii=False, indent=2)


if __name__ == "__main__":
    main()
```

Ce que chaque exception attrapée dans `summarize` couvre :

| Exception | Cas réel |
| --- | --- |
| `LlmUnavailable` | modèle éteint, trop lent, absent |
| `ValueError` | « Voici le résumé : {…} » : ce n'est pas du JSON pur |
| `KeyError` | JSON valide mais sans `resume` ou sans `urgence` |
| `TypeError` | le modèle renvoie une liste `[…]` au lieu d'un objet |
| `AttributeError` | `resume` vaut un nombre : `.strip()` n'existe pas |

`" ".join(mail.body.split())` ramène tous les blancs (espaces multiples, tabulations, sauts de ligne) à une espace simple : `split()` sans argument coupe sur n'importe quelle suite de blancs.

## Pas à pas : écrire digest.py

1. Écrivez les imports, le `sys.path.insert` vers `kit`, et les constantes.
2. Écrivez `load_mails` et testez-la dans `python3` : `len(load_mails("json", "kit/fixtures/mails.json"))`.
3. Écrivez `build_prompt` et affichez le prompt d'un mail avec `print` : relisez les trois parties.
4. Écrivez `fallback_summary` et testez-la sur un mail au corps vide.
5. Écrivez `summarize`, puis `main`.
6. Testez sans modèle (`OLLAMA_URL=http://127.0.0.1:9`, un port fermé) : chaque entrée doit venir du secours, et le code de sortie être `0`.
7. Testez avec le simulateur en mode `ok` : sa réponse est une phrase, pas du JSON, donc le secours doit encore s'appliquer.

**À retenir :** un prompt en trois parties avec délimiteur ; une sortie JSON toujours validée ; un corps coupé ; un secours extractif honnête ; une entrée par mail, dans l'ordre.
