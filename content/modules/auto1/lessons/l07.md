# Résumer des mails

Résumer, c'est le travail rêvé pour un modèle local. Mais un modèle bavarde, se trompe et parfois invente. Votre script doit donc lui poser une question précise, vérifier la réponse, et savoir se passer de lui. Rappel : les mails réels restent **en local** (Ollama), jamais envoyés à un service externe.

## Un prompt structuré

Un bon prompt a trois parties, toujours dans le même ordre : les **consignes**, un **délimiteur**, puis le **mail**. Les consignes disent le rôle, le format de sortie attendu et la règle « n'invente rien ». Le délimiteur, par exemple `--- MAIL ---`, marque où commence la donnée. Un mail par prompt : vous gardez ainsi le lien entre un mail et son résumé.

!!Un prompt vague comme « résume ça » donne une réponse différente à chaque appel et impossible à traiter par programme!!

## Demander du JSON, puis le valider

Demandez une réponse au format **JSON** avec des clés fixes : `urgence` et `resume`. Puis ne faites jamais confiance : lisez avec `json.loads`, vérifiez que c'est bien un objet, que l'urgence est dans la liste (`haute`, `normale`, `basse`) et que le résumé n'est pas vide. Une réponse qui ne passe pas la validation est traitée comme une panne.

!!Un `json.loads` sans `try` plante dès que le modèle ajoute « Voici le résumé : » devant le JSON!!

## Découper les gros corps

Un modèle a une fenêtre de contexte limitée, et chaque caractère coûte du temps. **Coupez le corps** à quelques milliers de caractères : le début d'un mail contient presque toujours l'essentiel. Coupez la fin, jamais le début.

## Le résumé extractif de secours

Quand le modèle est éteint, lent ou incohérent, le script produit un résumé **extractif** : un extrait du vrai mail, par exemple ses 200 premiers caractères, avec l'urgence déduite de mots-clés comme « urgent » ou « alerte ». Ce n'est pas brillant, mais c'est vrai, et la chaîne continue de tourner.

!!Un secours qui renvoie toujours « Résumé indisponible » ou une phrase inventée fait croire que le mail a été lu!!

## Ne rien inventer, garder l'ordre

Une entrée par mail, dans l'ordre de la source, même pour un mail vide. Le résumé ne doit contenir que ce qui est dans le mail : chiffres, dates et noms viennent du texte, pas de la mémoire du modèle.

## Exemple

```python
try:
    data = json.loads(generate(prompt, timeout=3))
    ok = data["urgence"] in ("haute", "normale", "basse") and data["resume"].strip()
except (LlmUnavailable, ValueError, KeyError, TypeError):
    ok = False
resultat = data if ok else fallback_summary(mail)
```

**À retenir :** un prompt en trois parties avec délimiteur ; une sortie JSON toujours validée ; un corps coupé ; un secours extractif honnête ; une entrée par mail, dans l'ordre.
