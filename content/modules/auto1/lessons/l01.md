# Un script qui sert vraiment

Un script utile, c'est un petit outil fiable : il dit ce qu'il fait, il s'arrête au premier problème et il ne perd rien. Aujourd'hui, vous écrivez le vôtre pour ranger un dossier `inbox/`.

## Le shebang et le mode strict

La première ligne indique quel programme lit le script : `#!/usr/bin/env bash`. On rend ensuite le fichier **exécutable** avec `chmod +x`.

Juste après, mettez `set -euo pipefail`. En clair : **stop à la première erreur**, **erreur si une variable n'existe pas**, et **une erreur dans un tube compte**. Sans cela, un script continue après un échec et fait des dégâts en silence.

## Arguments et codes de sortie

Le script reçoit ses arguments dans `$1`, `$2`… et leur nombre dans `$#`. Si l'appel est mauvais, on écrit un message `Usage` sur la sortie d'erreur et on sort avec le code **2**. Par convention, **0 veut dire succès**, tout autre nombre veut dire échec. C'est ce code que lisent les outils qui vous appellent.

!!Un script sans contrôle d'arguments travaille sur le mauvais dossier le jour où on oublie de le préciser!!

## Les noms avec espaces

C'est le piège numéro un. Le fichier `facture mars.pdf` contient une espace. Écrit sans guillemets, le shell le coupe en deux mots : `facture` et `mars.pdf`.

!!Toujours des guillemets doubles autour des variables : "$f", jamais $f!!

Utilisez aussi `mv -n -- "$f" "$cible"` : **-n** refuse d'écraser un fichier existant, et `--` protège les noms qui commencent par un tiret.

## Exemple court

```bash
for f in "$dossier"/*; do
  [ -f "$f" ] || continue
  nom=${f##*/}
  mkdir -p "$dossier/pdf"
  mv -n -- "$f" "$dossier/pdf/$nom"
done
```

`${f##*/}` garde seulement le nom du fichier. `${nom##*.}` donnerait son extension, et `${ext,,}` la met en minuscules : `photo.JPG` ira dans `jpg/`.

## Le script complet, ligne par ligne

```bash
#!/usr/bin/env bash
# Fichier : tri.sh   Usage : ./tri.sh <dossier>
set -euo pipefail                          # 1. TOUJOURS juste après le shebang

# 2. Contrôler les arguments AVANT de toucher au moindre fichier
if [ $# -ne 1 ]; then
  echo "Usage : $0 <dossier>" >&2          # >&2 : sur la sortie d'erreur
  exit 2                                   # 2 = mauvais usage
fi
dossier=$1
[ -d "$dossier" ] || { echo "Dossier introuvable : $dossier" >&2; exit 1; }

# 3. Le travail, fichier par fichier
for f in "$dossier"/*; do
  [ -f "$f" ] || continue                  # saute les sous-dossiers (dont ceux déjà créés)
  nom=${f##*/}                             # « inbox/Photo.JPG » → « Photo.JPG »
  if [[ "$nom" == *.* ]]; then
    ext=${nom##*.}                         # « Photo.JPG » → « JPG »
    ext=${ext,,}                           # → « jpg »
  else
    ext=sans_extension
  fi
  mkdir -p "$dossier/$ext"                 # -p : pas d'erreur si le dossier existe déjà
  mv -n -- "$f" "$dossier/$ext/$nom"       # -n : n'écrase jamais
done
```

Pourquoi cet ordre en trois blocs :

1. `set -euo pipefail` protège tout ce qui suit : placé plus bas, les lignes du dessus tourneraient sans filet.
2. Le contrôle d'arguments vient **avant** la boucle : si l'appel est faux, on sort sans avoir rien déplacé.
3. La boucle ne fait que des actions **réversibles** : créer un dossier, déplacer sans écraser.

Dans un `if` de bash, l'espace compte : `[ -d "$dossier" ]` avec une espace après `[` et avant `]`. `[-d "$dossier"]` donne `command not found`, car `[` est une commande.

Les trois expansions `${...}` se lisent ainsi :

| Écriture | Sens | `inbox/Facture Mars.PDF` |
| --- | --- | --- |
| `${f##*/}` | retire tout jusqu'au dernier `/` | `Facture Mars.PDF` |
| `${nom##*.}` | retire tout jusqu'au dernier `.` | `PDF` |
| `${ext,,}` | met en minuscules | `pdf` |

## Ne rien perdre

Un script de rangement **déplace, il ne supprime jamais**. Il doit aussi pouvoir être relancé sans casser ce qui est déjà rangé.

!!Un `rm` dans un script de tri est une erreur : testez d'abord sur des copies!!

!!Sans `set -u`, une variable mal écrite devient vide, et `rm -rf "$dossier/"` peut viser la racine!!

## Pas à pas : écrire et tester tri.sh

1. Créez `tri.sh` dans le dossier du TP. Ligne 1 : le shebang. Ligne 2 : `set -euo pipefail`.
2. Écrivez le contrôle d'arguments, puis rendez le fichier exécutable : `chmod +x tri.sh`.
3. Testez-le seul : `./tri.sh ; echo $?` doit afficher le message `Usage` et `2`.
4. Écrivez la boucle **sans** le `mv`, avec un `echo "$f -> $ext"` à la place : vous voyez ce qui serait fait.
5. Travaillez sur une copie : `cp -r inbox /tmp/essai && ./tri.sh /tmp/essai && find /tmp/essai`.
6. Quand l'affichage est bon, remplacez l'`echo` par `mkdir -p` et `mv -n --`.
7. Relancez le script une seconde fois sur la copie : rien ne doit bouger.

**À retenir :** shebang, `set -euo pipefail`, un contrôle d'arguments avec code 2, des guillemets partout, et jamais de suppression.
