# Un script qui sert vraiment

Un script utile, c'est un petit outil fiable : il dit ce qu'il fait, il s'arrête au premier problème et il ne perd rien. Aujourd'hui, vous écrivez le vôtre pour ranger un dossier `inbox/`.

## Le shebang et le mode strict

La première ligne indique quel programme lit le script : `#!/usr/bin/env bash`. On rend ensuite le fichier **exécutable** avec `chmod +x`.

Juste après, mettez `set -euo pipefail`. En clair : **stop à la première erreur**, **erreur si une variable n'existe pas**, et **une erreur dans un tube compte**. Sans cela, un script continue après un échec et fait des dégâts en silence.

## Arguments et codes de sortie

Le script reçoit ses arguments dans `$1`, `$2`… et leur nombre dans `$#`. Si l'appel est mauvais, on écrit un message `Usage` sur la sortie d'erreur et on sort avec le code **2**. Par convention, **0 veut dire succès**, tout autre nombre veut dire échec. C'est ce code que lisent les outils qui vous appellent.

!!Un script sans contrôle d'arguments travaille sur le mauvais dossier le jour où on oublie de le préciser!!

## Les noms avec espaces

C'est le piège numéro un. Le fichier `facture mars.pdf` contient une espace. Écrit sans guillemets, le shell le coupe en deux mots : `facture` et `mars.pdf`.

!!Toujours des guillemets doubles autour des variables : "$f", jamais $f!!

Utilisez aussi `mv -n -- "$f" "$cible"` : **-n** refuse d'écraser un fichier existant, et `--` protège les noms qui commencent par un tiret.

## Exemple court

```bash
for f in "$dossier"/*; do
  [ -f "$f" ] || continue
  nom=${f##*/}
  mkdir -p "$dossier/pdf"
  mv -n -- "$f" "$dossier/pdf/$nom"
done
```

`${f##*/}` garde seulement le nom du fichier. `${nom##*.}` donnerait son extension, et `${ext,,}` la met en minuscules : `photo.JPG` ira dans `jpg/`.

## Ne rien perdre

Un script de rangement **déplace, il ne supprime jamais**. Il doit aussi pouvoir être relancé sans casser ce qui est déjà rangé.

!!Un `rm` dans un script de tri est une erreur : testez d'abord sur des copies!!

!!Sans `set -u`, une variable mal écrite devient vide, et `rm -rf "$dossier/"` peut viser la racine!!

**À retenir :** shebang, `set -euo pipefail`, un contrôle d'arguments avec code 2, des guillemets partout, et jamais de suppression.
