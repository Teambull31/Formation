# Appeler une API

Un script utile parle presque toujours à un service : tâches, mails, météo. Il le fait par HTTP, avec une **requête** et une **réponse**.

## GET, POST et en-têtes

**GET** lit une donnée, sans rien changer. **POST** envoie une donnée pour créer quelque chose. Pour envoyer du JSON, ajoutez l'en-tête `Content-Type: application/json` et un corps JSON. Avec curl : `curl -s -X POST -H 'Content-Type: application/json' -d '{"title":"x"}' "$API_URL/tasks"`.

## Les codes de statut

Le premier chiffre dit tout. **2xx** : succès. **4xx** : c'est votre requête qui est fausse (404 introuvable, 400 mauvais corps). **5xx** : c'est le serveur qui a un problème, souvent passager.

!!Ne rejouez jamais une erreur 4xx : la même requête donnera la même erreur!!

## Toujours un timeout

Sans limite de temps, un serveur muet bloque votre script pour toujours. Fixez un **timeout** à chaque appel, par exemple 2 secondes.

!!Sans timeout, une API lente gèle toute votre automatisation, et cron empile les copies bloquées!!

## Réessayer avec un backoff

Une panne passagère (5xx, timeout, connexion refusée) mérite un nouvel essai. Faites **3 tentatives** au plus, avec une pause qui double : 0,2 s, puis 0,4 s. C'est le **backoff**. Sans pause, vous martelez un serveur déjà en difficulté.

## POST : pas de retry aveugle

Un GET est **idempotent** : le refaire ne change rien. Un POST ne l'est pas. Si la réponse se perd après la création, un retry crée un doublon : deux factures, deux mails envoyés.

!!Ne réessayez jamais un POST à l'aveugle : vous risquez des doublons!!

Notre règle : **GET réessayé jusqu'à 3 fois, POST une seule fois**. Un échec final se termine par un message lisible et un code de sortie non nul, pas par une trace Python.

## Exemple

```python
import json, urllib.request
req = urllib.request.Request(url, method="POST",
    data=json.dumps({"title": "x"}).encode(),
    headers={"Content-Type": "application/json"})
with urllib.request.urlopen(req, timeout=2) as r:
    print(r.status, json.load(r))
```

`urlopen` lève `HTTPError` pour 4xx et 5xx, et `URLError` si le serveur est injoignable.

**À retenir :** timeout toujours, 3 essais avec backoff pour les GET sur 5xx ou panne réseau, jamais pour les 4xx, un seul essai pour un POST.
