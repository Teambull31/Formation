# Appeler une API

Un script utile parle presque toujours à un service : tâches, mails, météo. Il le fait par HTTP, avec une **requête** et une **réponse**.

## GET, POST et en-têtes

**GET** lit une donnée, sans rien changer. **POST** envoie une donnée pour créer quelque chose. Pour envoyer du JSON, ajoutez l'en-tête `Content-Type: application/json` et un corps JSON. Avec curl : `curl -s -X POST -H 'Content-Type: application/json' -d '{"title":"x"}' "$API_URL/tasks"`.

## Les codes de statut

Le premier chiffre dit tout. **2xx** : succès. **4xx** : c'est votre requête qui est fausse (404 introuvable, 400 mauvais corps). **5xx** : c'est le serveur qui a un problème, souvent passager.

!!Ne rejouez jamais une erreur 4xx : la même requête donnera la même erreur!!

## Toujours un timeout

Sans limite de temps, un serveur muet bloque votre script pour toujours. Fixez un **timeout** à chaque appel, par exemple 2 secondes.

!!Sans timeout, une API lente gèle toute votre automatisation, et cron empile les copies bloquées!!

## Réessayer avec un backoff

Une panne passagère (5xx, timeout, connexion refusée) mérite un nouvel essai. Faites **3 tentatives** au plus, avec une pause qui double : 0,2 s, puis 0,4 s. C'est le **backoff**. Sans pause, vous martelez un serveur déjà en difficulté.

## POST : pas de retry aveugle

Un GET est **idempotent** : le refaire ne change rien. Un POST ne l'est pas. Si la réponse se perd après la création, un retry crée un doublon : deux factures, deux mails envoyés.

!!Ne réessayez jamais un POST à l'aveugle : vous risquez des doublons!!

Notre règle : **GET réessayé jusqu'à 3 fois, POST une seule fois**. Un échec final se termine par un message lisible et un code de sortie non nul, pas par une trace Python.

## Exemple

```python
import json, urllib.request
req = urllib.request.Request(url, method="POST",
    data=json.dumps({"title": "x"}).encode(),
    headers={"Content-Type": "application/json"})
with urllib.request.urlopen(req, timeout=2) as r:
    print(r.status, json.load(r))
```

`urlopen` lève `HTTPError` pour 4xx et 5xx, et `URLError` si le serveur est injoignable.

## Le client complet, bloc par bloc

```python
# Fichier : client.py
import json
import os
import sys
import time
import urllib.error
import urllib.request

TIMEOUT = 2          # constantes en haut : on les retrouve et on les change en un seul endroit
ESSAIS = 3


def appel(methode, url, corps=None):
    """Un seul essai : renvoie le JSON de la réponse, ou lève une exception."""
    data = json.dumps(corps).encode() if corps is not None else None
    req = urllib.request.Request(url, method=methode, data=data,
                                 headers={"Content-Type": "application/json"})
    with urllib.request.urlopen(req, timeout=TIMEOUT) as r:
        return json.load(r)


def get(url):
    """GET avec 3 essais : on réessaie les pannes passagères, jamais un 4xx."""
    pause = 0.2
    for essai in range(1, ESSAIS + 1):
        try:
            return appel("GET", url)
        except urllib.error.HTTPError as e:
            if e.code < 500 or essai == ESSAIS:   # 4xx : inutile de réessayer
                raise                             # dernier essai : on abandonne
        except (urllib.error.URLError, TimeoutError):
            if essai == ESSAIS:
                raise
        time.sleep(pause)                         # 0,2 s puis 0,4 s
        pause *= 2


def main():
    base = os.environ.get("API_URL")
    if not base:
        raise RuntimeError("la variable API_URL est absente")
    for t in get(f"{base}/tasks"):
        print(f"{t['id']}: {t['title']}")
    print("flaky:", json.dumps(get(f"{base}/flaky")))
    cree = appel("POST", f"{base}/tasks", {"title": "Relancer le client"})   # un seul essai
    print("créée:", cree["id"])


if __name__ == "__main__":
    try:
        main()
    except Exception as e:                        # filet final : une phrase, pas une trace
        print(f"Échec : {e}", file=sys.stderr)
        sys.exit(1)
```

Le découpage suit les règles de la leçon :

- `appel` fait **un** essai, pour n'importe quelle méthode : le POST l'utilise directement, donc il n'est jamais rejoué.
- `get` ajoute la boucle de réessai autour d'`appel` : seul le GET est réessayé.
- `main` ne contient que le scénario, dans l'ordre demandé.
- Le bloc `if __name__ == "__main__":` en bas transforme toute exception en message lisible et en code 1.

Dans la boucle de `get`, l'ordre des `except` compte : `HTTPError` est une sous-classe de `URLError`. Placé en second, il ne serait jamais atteint, et un 404 serait réessayé comme une panne réseau.

## Pas à pas : écrire client.py

1. Démarrez le serveur de test dans un premier terminal (commande dans l'énoncé du TP) et notez le port.
2. Dans un second terminal : `export API_URL=http://127.0.0.1:PORT`, puis `curl -s "$API_URL/tasks"` pour voir la forme des données.
3. Écrivez `appel` et testez-la seule dans `python3`, sur `/tasks`.
4. Ajoutez `get` avec sa boucle. Testez sur `/flaky` : il doit finir par répondre.
5. Écrivez `main`, puis le bloc final qui attrape les exceptions.
6. Arrêtez le serveur et relancez le client : un message d'une ligne, et `echo $?` affiche `1`.

**À retenir :** timeout toujours, 3 essais avec backoff pour les GET sur 5xx ou panne réseau, jamais pour les 4xx, un seul essai pour un POST.
