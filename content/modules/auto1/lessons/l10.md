# Brancher Outlook

Jusqu'ici, vos mails venaient d'un fichier. Pour une vraie boîte Outlook, on passe par **Microsoft Graph**, l'API de Microsoft. Vous avez déjà tout appris : c'est un appel d'API (leçon 3) derrière votre interface de source (leçon 5). Le kit fournit `OutlookGraphSource`.

## Perso ou pro

Un compte **personnel** (outlook.com) s'essaie seul, sans demander la permission : c'est le tenant `consumers`. Un compte **professionnel** dépend de l'entreprise : enregistrement de l'application, consentement d'un administrateur, règles de sécurité. !!Ne branchez jamais la boîte pro sans l'accord écrit du service informatique!!

Les étapes réelles sont dans `kit/FICHE_perso_vers_pro.md`. L'essai réel avec votre compte perso est une **étape manuelle facultative**, hors du contrôle automatique du TP : le contrôle n'utilise que le simulateur.

## Se connecter : le device code flow

Votre script n'a pas de navigateur. Le **device code flow** affiche une adresse et un code : vous les saisissez dans un navigateur, vous acceptez, et le script reçoit un **jeton**. Pas de mot de passe dans le script.

!!Un jeton est un mot de passe : jamais dans un dépôt git, jamais dans un log, jamais affiché!!

Le jeton est stocké dans un fichier en **0600** (lisible par vous seul). Le kit le fait pour vous ; vérifiez-le avec `ls -l`. Il le range dans `~/.config/formation-auto1/` (dossier utilisateur), **jamais à côté du script**. Dans le TP, le script lit l'emplacement dans la variable `GRAPH_TOKEN_PATH` : le contrôle la fixe vers un dossier jetable. En vrai, ne la définissez pas.

## Lecture seule : `Mail.Read`

Demandez le **moindre privilège** : le droit `Mail.Read`, rien d'autre. Pas `Mail.ReadWrite`, pas `Mail.Send`. Le connecteur ne fait que des requêtes **GET**, sur un seul serveur.

!!Si un jour une page de consentement réclame « envoyer des mails en votre nom », arrêtez : ce n'est pas le bon droit!!

## `$select` et pagination

Graph renvoie les mails **par pages**. Chaque page indique la suivante dans `@odata.nextLink` : le connecteur la suit, une fois chacune, avec une limite. Il demande seulement les champs utiles avec **`$select`** (id, objet, expéditeur, date, corps) : moins de données reçues, moins de données à protéger.

Dans votre code et vos logs : des **compteurs** (« 12 mails »), jamais de **corps** de mail.

## Le programme complet

Remarquez l'**ordre des imports** : `import digest` vient en premier, car c'est lui qui ajoute `kit/` au chemin de Python. Importé avant, `outlook_graph` serait introuvable.

```python
# Fichier : outlook_digest.py
# Usage : GRAPH_URL=http://127.0.0.1:PORT/v1.0 python3 outlook_digest.py [--out digest.json]
import argparse
import json
import os
import sys

import digest                                     # 1. en premier : ajoute kit/ au sys.path
from mail_source import ConnectorError            # 2. ensuite seulement, les modules du kit
from outlook_graph import OutlookGraphSource


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--out", default="digest.json")
    args = ap.parse_args()
    try:
        url = os.environ.get("GRAPH_URL")
        if not url:
            raise RuntimeError("la variable GRAPH_URL est absente")
        source = OutlookGraphSource(
            "client-id-fictif",
            base_url=url,                                       # jamais une adresse en dur
            auth=lambda: "jeton-fictif",                        # le vrai device code flow est manuel
            token_path=os.environ.get("GRAPH_TOKEN_PATH"),      # None en vrai : le kit choisit, en 0600
        )
        mails = source.fetch(limit=10_000)                      # le connecteur suit les pages
    except (ConnectorError, RuntimeError) as e:
        print(f"Échec de la lecture Outlook : {e}", file=sys.stderr)
        sys.exit(1)                                             # et digest.json n'est PAS écrit
    entrees = [digest.digest_entry(m) for m in mails]           # même chemin que les autres sources
    with open(args.out, "w", encoding="utf-8") as f:
        json.dump(entrees, f, ensure_ascii=False, indent=2)
    print(f"{len(entrees)} mails traités")                      # un compteur, jamais un contenu


if __name__ == "__main__":
    main()
```

Le `try` entoure la **lecture** seulement. Si elle échoue, on sort avant d'avoir ouvert `digest.json` : un fichier à moitié vide ferait croire que la boîte était vide. Le traitement des mails, lui, est celui des leçons 7 et 8, sans changement : c'est tout l'intérêt du contrat `MailSource`.

## Pas à pas : brancher le simulateur Graph

1. Démarrez le simulateur dans un premier terminal (commande dans l'énoncé du TP) et notez le port.
2. Dans un second terminal : `export GRAPH_URL=http://127.0.0.1:PORT/v1.0` et `export GRAPH_TOKEN_PATH=$(mktemp -d)/token.json`.
3. Écrivez les imports dans l'ordre ci-dessus, et vérifiez-les : `python3 -c "import outlook_digest"` ne doit rien afficher.
4. Écrivez la construction de la source et un `print(len(source.fetch(limit=10_000)))` provisoire : il doit afficher `12`.
5. Remplacez ce `print` par la boucle `digest_entry` et l'écriture de `digest.json`.
6. Testez les erreurs : arrêtez le simulateur, relancez, puis `echo $?` doit afficher `1`, et `ls digest.json` ne doit rien montrer de nouveau.
7. Relisez la sortie : un compteur, ni jeton, ni objet, ni corps.

**À retenir :** Graph en lecture seule (`Mail.Read`) ; device code flow ; jeton en 0600 ; `$select` et pages ; jamais de corps ni de jeton dans les logs.
