# Le digest quotidien, prêt à déployer

Votre digest marche. Pour qu'il serve vraiment, il doit tourner **tout seul, chaque jour**, sans jamais refaire deux fois le même travail et sans tomber si Ollama dort. C'est la différence entre un script et un outil.

## Idempotent : un mail, une fois

Un mail a un `id`. Le digest garde la liste des `id` déjà traités dans un **fichier d'état**. Au passage suivant, il ignore ces mails. Relancer le script (par erreur, après une panne, deux fois dans la même minute) ne change donc rien : le fichier du jour reste identique.

!!Si vous relancez et que le digest contient chaque mail en double, le script n'est pas idempotent!!

Le résumé d'un mail déjà traité n'est **jamais recalculé** : on le garde dans l'état. Sinon le digest d'hier changerait selon l'humeur du modèle.

## Un état qui survit aux accidents

Écrivez le fichier dans un fichier temporaire, puis remplacez-le d'un coup (`os.replace`) : c'est **atomique**. Si la machine s'éteint pendant l'écriture, vous avez l'ancien fichier entier, jamais un demi-fichier. Écrivez le digest **avant** l'état : en cas de coupure, le pire est de traiter un mail une seconde fois, jamais d'en perdre un.

!!Un fichier d'état abîmé ne doit pas faire planter le script : repartez de zéro et continuez!!

## Le journal : des compteurs

Chaque exécution ajoute **une ligne** au journal : l'heure, le jour, combien de mails nouveaux, combien ignorés, si le modèle a répondu. Ouvrez-le en mode ajout. !!Jamais de contenu de mail dans le journal : mails réels, local uniquement!!

## Si Ollama est en panne

Le digest doit sortir quand même. **Sondez le modèle une seule fois**. S'il ne répond pas, passez en **secours** (`fallback_summary`, sans IA) pour tous les mails au lieu d'attendre un délai par mail. Notez `modele=secours` dans le journal. Les mails suspects, eux, ne vont jamais au modèle.

## Planifier, puis déployer

Planifiez avec cron (leçon 2) : **chemins absolus**, `>>` pour les erreurs, `\%` à la place de `%`, un `PATH` explicite. Avec un timer utilisateur, `loginctl enable-linger` pour tourner sans session ouverte.

Avant de brancher une vraie boîte **au travail**, passez la checklist : **accord écrit du service informatique** ; droit de lecture seule seulement ; secrets (jeton, mot de passe) hors du code et du dépôt ; modèle local, aucune donnée vers l'extérieur ; essai d'abord sur des mails jetables ; un journal relu et une personne qui sait ce que fait l'outil.

!!Pas d'accord du service informatique, pas de déploiement sur la boîte pro!!

**À retenir :** idempotence par `id` avec un état dans un fichier écrit de façon atomique ; un journal de compteurs ; secours quand Ollama est en panne ; planification avec chemins absolus ; et pas de déploiement au travail sans l'accord du service informatique.
