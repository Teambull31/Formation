# Le digest quotidien, prêt à déployer

Votre digest marche. Pour qu'il serve vraiment, il doit tourner **tout seul, chaque jour**, sans jamais refaire deux fois le même travail et sans tomber si Ollama dort. C'est la différence entre un script et un outil.

## Idempotent : un mail, une fois

Un mail a un `id`. Le digest garde la liste des `id` déjà traités dans un **fichier d'état**. Au passage suivant, il ignore ces mails. Relancer le script (par erreur, après une panne, deux fois dans la même minute) ne change donc rien : le fichier du jour reste identique.

!!Si vous relancez et que le digest contient chaque mail en double, le script n'est pas idempotent!!

Le résumé d'un mail déjà traité n'est **jamais recalculé** : on le garde dans l'état. Sinon le digest d'hier changerait selon l'humeur du modèle.

## Un état qui survit aux accidents

Écrivez le fichier dans un fichier temporaire, puis remplacez-le d'un coup (`os.replace`) : c'est **atomique**. Si la machine s'éteint pendant l'écriture, vous avez l'ancien fichier entier, jamais un demi-fichier. Écrivez le digest **avant** l'état : en cas de coupure, le pire est de traiter un mail une seconde fois, jamais d'en perdre un.

!!Un fichier d'état abîmé ne doit pas faire planter le script : repartez de zéro et continuez!!

## Le journal : des compteurs

Chaque exécution ajoute **une ligne** au journal : l'heure, le jour, combien de mails nouveaux, combien ignorés, si le modèle a répondu. Ouvrez-le en mode ajout. !!Jamais de contenu de mail dans le journal : mails réels, local uniquement!!

## Choisir et réchauffer le modèle

Le kit lit le modèle dans la variable `OLLAMA_MODEL` (défaut `qwen3:14b`) et désactive le mode « réflexion ». Un modèle froid peut mettre plus de 60 s à répondre : lancez-le une fois à la main avant le premier passage, ou augmentez `OLLAMA_TIMEOUT`.

## Si Ollama est en panne

Le digest doit sortir quand même. **Sondez le modèle une seule fois**. S'il ne répond pas, passez en **secours** (`fallback_summary`, sans IA) pour tous les mails au lieu d'attendre un délai par mail. Notez `modele=secours` dans le journal. Les mails suspects, eux, ne vont jamais au modèle.

!!Un délai trop court sonne « panne » à tort : un modèle froid met plusieurs secondes à se charger!! Le délai se règle avec la variable **`OLLAMA_TIMEOUT`** (60 s par défaut dans `digest.py`) ; utilisez le même pour le sondage. Sondez seulement s'il y a un mail à résumer.

## Les fichiers produits, en exemple

Après deux jours de fonctionnement, voici ce que contient chaque fichier. Les comprendre avant d'écrire le code donne la forme des données à manipuler.

```json
{
 "traites": {
  "m-101": {"date": "2026-03-01", "urgence": "haute",   "resume": "Facture à régler avant le 15.", "suspect": false},
  "m-102": {"date": "2026-03-01", "urgence": "normale", "resume": "Mail suspect : contenu non résumé, à vérifier.", "suspect": true},
  "m-103": {"date": "2026-03-02", "urgence": "basse",   "resume": "Newsletter de mars.", "suspect": false}
 }
}
```

```text
# Digest du 2026-03-01

- [haute] m-101 : Facture à régler avant le 15.
- [normale] m-102 : Mail suspect : contenu non résumé, à vérifier. [SUSPECT]
```

```text
2026-03-01T12:15:02 date=2026-03-01 nouveaux=2 ignores=0 modele=ok
2026-03-01T12:20:40 date=2026-03-01 nouveaux=0 ignores=2 modele=ok
2026-03-02T12:15:01 date=2026-03-02 nouveaux=1 ignores=2 modele=secours
```

Le premier bloc est l'**état** (`etat.json`) : un dictionnaire `id → résumé`, qui sert à la fois de mémoire (« déjà traité ? ») et de source pour réécrire le digest d'un jour. Le deuxième est le **digest** du 1er mars. Le troisième est le **journal** : la deuxième ligne montre une relance le même jour, sans aucun nouveau mail.

## Le programme complet, bloc par bloc

```python
# Fichier : quotidien.py   Usage : python3 quotidien.py --path FICHIER [--date AAAA-MM-JJ] …
import argparse
import json
import os
import sys
from datetime import date, datetime
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parent))
import digest                                   # noqa: E402  ajoute aussi kit/ au chemin
from llm import LlmUnavailable, generate        # noqa: E402

ORDRE = {"haute": 0, "normale": 1, "basse": 2}


# ── L'état : lu avec tolérance, écrit de façon atomique ──
def charger_etat(path):
    try:
        traites = json.loads(Path(path).read_text(encoding="utf-8"))["traites"]
    except (OSError, ValueError, KeyError, TypeError):
        return {}                               # absent ou abîmé : on repart de zéro
    return traites if isinstance(traites, dict) else {}


def ecrire(path, texte):
    tmp = f"{path}.tmp"
    with open(tmp, "w", encoding="utf-8") as f:
        f.write(texte)                          # 1. tout le contenu dans un fichier à part
    os.replace(tmp, path)                       # 2. bascule d'un coup : jamais de demi-fichier


# ── Le modèle : sondé une seule fois ──
def modele_disponible():
    try:
        generate("ping", timeout=digest.llm_timeout())   # OLLAMA_TIMEOUT, 60 s par défaut
        return True
    except LlmUnavailable:
        return False


# ── Le rendu : uniquement à partir de l'état ──
def une_ligne(texte):
    return " ".join(str(texte).split())         # retours à la ligne et espaces multiples → une espace


def rendu(jour, traites):
    lignes = [(ORDRE.get(e["urgence"], 1), i, e) for i, e in traites.items() if e["date"] == jour]
    lignes.sort(key=lambda t: t[0])             # tri STABLE : à urgence égale, l'ordre de traitement reste
    corps = [f"- [{e['urgence']}] {une_ligne(i)} : {une_ligne(e['resume'])}"
             + (" [SUSPECT]" if e["suspect"] else "")
             for _, i, e in lignes] or ["Aucun nouveau mail."]
    return f"# Digest du {jour}\n\n" + "\n".join(corps) + "\n"


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--path", required=True)
    ap.add_argument("--source", choices=["json", "mbox"], default="json")
    ap.add_argument("--date", default=date.today().isoformat())
    ap.add_argument("--state", default="etat.json")
    ap.add_argument("--out-dir", default=".")
    ap.add_argument("--log", default="quotidien.log")
    args = ap.parse_args()

    traites = charger_etat(args.state)
    mails = digest.load_mails(args.source, args.path)
    modele, secours, nouveaux = None, False, 0  # None = pas encore sondé
    for m in mails:
        if m.id in traites:
            continue                            # déjà connu : jamais recalculé
        if digest.is_suspect(m):
            entree = digest.digest_entry(m)     # ne va jamais au modèle
        else:
            if modele is None:
                modele = modele_disponible()    # la sonde, une seule fois, et seulement si besoin
            if modele:
                entree = digest.digest_entry(m)
            else:
                secours = True
                entree = {"id": m.id, **digest.fallback_summary(m), "suspect": False}
        traites[m.id] = {"date": args.date, "urgence": entree["urgence"],
                         "resume": entree["resume"], "suspect": entree["suspect"]}
        nouveaux += 1

    os.makedirs(args.out_dir, exist_ok=True)
    ecrire(os.path.join(args.out_dir, f"digest-{args.date}.md"), rendu(args.date, traites))  # d'abord le digest
    ecrire(args.state, json.dumps({"traites": traites}, ensure_ascii=False, indent=1))    # puis l'état
    with open(args.log, "a", encoding="utf-8") as f:                                      # « a » : ajout
        f.write(f"{datetime.now().isoformat(timespec='seconds')} date={args.date} "
                f"nouveaux={nouveaux} ignores={len(mails) - nouveaux} "
                f"modele={'secours' if secours else 'ok'}\n")


if __name__ == "__main__":
    main()
```

Les trois choix qui rendent l'outil fiable :

- **Le rendu ne lit que l'état**, jamais les mails : relancer le même jour réécrit exactement le même fichier, octet pour octet.
- **Le digest est écrit avant l'état.** Si la machine s'éteint entre les deux, l'état ignore encore les nouveaux mails : au prochain passage, ils sont traités une seconde fois. On préfère un doublon à une perte.
- **La sonde est paresseuse** (`modele is None`) : pas de mail à résumer, pas d'appel au modèle ; modèle en panne, un seul délai d'attente pour toute l'exécution.

## Pas à pas : écrire quotidien.py

1. Écrivez `charger_etat` et `ecrire`, et testez-les seules : un état absent, un état qui contient `{`, puis un aller-retour écrire et relire.
2. Écrivez `une_ligne` et `rendu`, et testez `rendu` sur un petit dictionnaire écrit à la main.
3. Écrivez `main` sans le modèle d'abord : tous les mails en `fallback_summary`.
4. Lancez deux fois `python3 quotidien.py --path kit/fixtures/mails.json --date 2026-03-01`, puis comparez les deux digests avec `md5sum` : identiques.
5. Ajoutez la sonde et l'aiguillage suspect, modèle, secours.
6. Testez la panne avec `OLLAMA_URL=http://127.0.0.1:9 OLLAMA_TIMEOUT=3` : la dernière ligne du journal doit finir par `modele=secours`.
7. Vérifiez qu'aucun `.tmp` ne traîne : `ls *.tmp` ne doit rien trouver.

## Planifier, puis déployer

Planifiez avec cron (leçon 2) : **chemins absolus**, `>> journal 2>&1` pour garder aussi les erreurs, `\%` à la place de `%`, un `PATH` explicite. Avec un timer utilisateur, `loginctl enable-linger` pour tourner sans session ouverte.

Avant de brancher une vraie boîte **au travail**, passez la checklist : **accord écrit du service informatique** ; droit de lecture seule seulement ; secrets (jeton, mot de passe) hors du code et du dépôt ; modèle local, aucune donnée vers l'extérieur ; essai d'abord sur des mails jetables ; un journal relu et une personne qui sait ce que fait l'outil.

!!Pas d'accord du service informatique, pas de déploiement sur la boîte pro!!

**À retenir :** idempotence par `id` avec un état dans un fichier écrit de façon atomique ; un journal de compteurs ; secours quand Ollama est en panne ; planification avec chemins absolus ; et pas de déploiement au travail sans l'accord du service informatique.
