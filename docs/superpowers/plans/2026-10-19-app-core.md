# Appli de formation gamifiée : socle V1, plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Une appli web locale où l'on suit une quête quotidienne (leçon écrite avec audio, QCM, TP vérifié par script dans un terminal), avec XP, rangs, équipe/gacha, boss, répétition espacée et écran de préparation hebdomadaire.

**Architecture:** Backend Python FastAPI + SQLite (stdlib `sqlite3`, pas d'ORM) ; contenu des modules en fichiers (Markdown + JSON) chargés et validés par un seul module ; frontend React servi en statique par FastAPI. Le terminal est un websocket pty limité à localhost ; Ollama sert aux indices avec repli sur les indices pré-écrits.

**Tech Stack:** Python >=3.12 géré par `uv` (3.14 installé), FastAPI, uvicorn, httpx, pytest ; Node 22, Vite, React, TypeScript, vitest, xterm.js ; Ollama (`qwen3:14b` déjà installé) ; `espeak-ng` (installé) pour l'audio.

**Spec:** `docs/superpowers/specs/2026-10-18-formation-gamifiee-design.md`

**Hors de ce plan (plans suivants, à écrire après celui-ci) :** (2) contenu du module 1 « automatisation et agents » avec l'interface `MailSource`, les connecteurs Outlook et Gmail et la fiche « du perso au pro » ; (3) « Veille du jour » ; (4) modules DevOps ; (5) vidéo. Ce plan fournit un module de démonstration (`backend/tests/fixtures/demo_module`) pour tout tester sans attendre le contenu réel.

## Global Constraints

- Interface et contenus en français ; termes techniques en anglais.
- Tout en local, un seul utilisateur, pas de comptes, pas de cloud, aucune clé API obligatoire.
- Le terminal, les vérifications de TP, les tentatives de boss et l'import de module ne répondent qu'à `127.0.0.1` ou `::1` (réponse 403 sinon) ; le reste de l'API est joignable depuis le téléphone sur le réseau local.
- Le gacha ne distribue que du cosmétique (personnages, skins) ; jamais de contenu de cours.
- Jours de repos annoncés : illimités, sans pénalité. Un sujet imposé ne casse pas la série.
- Séance : 30 min minimum, 60 min idéal ; quête du jour = 3 étapes (leçon, QCM, TP) ; quête bonus = 30 min en plus.
- Points clés d'un cours : `**gras**` et `!!rouge!!` dans le Markdown.
- La réussite d'un TP se décide par script, jamais par le LLM ; Qwen ne sert qu'aux indices et explications, avec repli sur le contenu pré-écrit.
- Un indice coûte 10 XP (choix du concepteur, ajustable dans `progress.py`).
- Aucune donnée personnelle ou mail réel ne sort de la machine.

## Review Focus

- Ollama éteint, lent ou en erreur : la séance continue avec les indices pré-écrits (test dans la tâche 5).
- Série après un jour sans activité avec repos annoncé, ou pendant un sujet imposé : pas de rupture (tâche 3).
- Script de vérification de TP qui boucle ou affiche des mégaoctets : coupé par timeout, sortie tronquée (tâche 6).
- Téléphone sur le réseau local qui appelle le terminal ou `/api/tp/*/check` : 403 (tâche 8).
- Module importé avec un QCM sans bonne réponse ou une réponse hors liste : refus avec message lisible, rien n'est copié (tâches 1, 9 et 10).
- Invocation avec 0 jeton : erreur, solde jamais négatif (tâche 9).
